# ETSA standalone product and consented opportunities

The landing and private discovery can ship independently. ETSA personal assessment, human scoring, and paid reassessment remain unchanged. Placement and founder referral writes, reviewer decisions, and scheduling requests default OFF; withdrawal stays available.

1. Apply `supabase/migrations/20261126000100_etsa_candidate_referrals.sql` in a staging project. Set `ETSA_REFERRALS_STORAGE_READY=true` only after the migration exists in that deployment’s database. Verify the service role can access the restricted queue and direct anon/authenticated actions are denied. The candidate routes derive identity from authenticated session ownership, require a server-generated results/report pair, and honor existing reassessment entitlement.
2. If email alerts are wanted, set `ETSA_RESEND_API_KEY` and `ETSA_NOTIFICATION_FROM` with a provider-verified sender. Disable open/link tracking for this transactional stream in the provider configuration. The recipient is fixed to `yourthing@polarpaw.online`. The alert contains no candidate name, contact, answers, scores, preferences, or recommendation, only the generic authenticated Founder queue link. Credentials are not required to store a secure request, but an email is not attempted without both. A first time request has its own notification state. A reviewer can manually retry unconfirmed provider submissions; retries reuse the event’s stable idempotency key and the application refuses repeats once provider acceptance is recorded.
3. Use synthetic accounts in the nonproduction deployment. Confirm personal discovery doesn’t create referral records; consented placement opens a queue item; opt-out clears shared details; only a Founder role can make a candidate invitation; a candidate date/time request is not a confirmed slot. Check mobile navigation and both cross-links. A person checks role-specific requirements and evidence, not whether someone’s general score crosses a threshold.
4. In Production set `ETSA_OPPORTUNITY_REFERRALS_ENABLED=true` and redeploy only after approving the review workflow and configuring monitoring. Unset the opportunity feature flag or set it false and redeploy to stop new submissions, decisions, and scheduling without deleting records. Leave `ETSA_REFERRALS_STORAGE_READY=true` so previously shared candidates can read and withdraw. Keep both flags false for a marketing-only rollout without a migration. An approved founder referral offers a conversation about terms; it never applies a coupon or changes checkout. Verified team phone is the immediate channel; there is no staff availability integration or calendar booking.

## Confirmed founder offer and SMS

The standard public Blueprint remains $499. After migrating `20261126000200_etsa_founder_offer_confirmation.sql`, set `ETSA_FOUNDER_OFFER_STORAGE_READY=true` in the environment that has the schema. Until then, prior invites remain discussion-only. This storage flag adds no consent and does not enable new referrals. For a consented and finalized founder referral, the authorized reviewer attests to having independently reviewed the evidence before confirming the fixed $349 offer. Confirmation alone does not issue invoices or create payment sessions.

To redeem, staff re-open the consented row, confirm the account email and an outstanding confirmed offer, and check Stripe for any existing invoice for that candidate and offer. Using the existing verified Stripe account, staff issue a private customer-specific invoice for the $349 Blueprint service fee under the approved tax/terms setup, then record that invoice's reference in the reviewer console. The console records a staff-entered reference (not payment or delivery verification); use Stripe to verify the invoice amount, customer, and payment. Do not issue an invoice for withdrawn, unconfirmed, or already issued offers. Never send a public price link, coupon, or URL. There is no automatic checkout or automatic delivery. Candidate SMS uses the published business number with a blank composer; the candidate must press Send. Preferred time remains a request, not a booking.
